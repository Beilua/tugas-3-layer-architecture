# Mission: 3-Layer Web Application Architecture

## Why
Complete the group assignment: build and present a Customer Management System that demonstrates Non-Layered vs 3-Layer Web Application Architecture with PHP native + MySQL and full CRUD. Understanding which files own presentation, business logic, and data is what the presentation will be judged on.

## Success looks like
- You can point to any file in this repo and say which layer owns it and why.
- You can explain the REST API + JSON request flow for Tambah / Edit / Hapus without looking.
- You can answer the 5 slide questions (easier to build? fix? extend? one-file risk? always worse?) in your own words.
- You can run both apps (import `db_customer.sql`, open `app-1-layer/` and `app-3-layer/presentation/`) and explain what you see.

## Constraints
- PHP native (no framework) + `mysqli` + MySQL, as required by the assignment.
- Short lessons: one tightly-scoped win per lesson. Ask follow-up questions to the teacher instead of guessing.
- This mission was inferred from `README.md`, `ANALISIS.md`, and the slide PDF (`3-Layer Web Application Architecture.pdf`). Confirm or correct it — missions change as you learn.

## Out of scope
- Frameworks (Laravel, Django, Spring Boot) — mentioned in slides as examples, not used in this assignment.
- Frontend frameworks (React/Vue/Angular) — the 3-layer app here uses vanilla HTML/CSS/JS + `fetch()`.
- Production hardening, auth, and deployment — not required for this assignment.
